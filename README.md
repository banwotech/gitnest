# GitNest

面向前后端多仓库项目的本地 Git 桌面客户端。可以打开没有 `.git` 的父文件夹，集中查看一级子仓库的分支与未提交文件，并逐个查看完整文件的左右差异。

## 运行

需要 Node.js 22.12+（推荐 Node.js 24）和 Git。macOS 可通过 Xcode Command Line Tools 提供 Git。

```bash
npm install
npm run dev
```

构建并打开桌面版：

```bash
npm run build
npm start
```

生成当前系统的应用目录或 macOS 安装包：

```bash
npm run pack
npm run dist
```

## 使用

1. 在欢迎页选择文件夹，或使用「文件 → 打开工作区」/ `⌘O`，选择前后端项目共同的父文件夹，也可以直接选择一个 Git 仓库。左侧工作区名称旁的上下箭头可以切换最近的工作区。
2. 左侧只展示当前目录和一级子目录中独立的 Git 仓库、当前分支及未提交文件数，普通子文件夹不显示。支持 `.git` 文件形式的 Git worktree。
3. 文件列表分为「未暂存」和「已暂存」。选择文件后，在右侧差异工具栏点击「暂存」或「取消暂存」，组标题提供批量操作；搜索时批量操作只影响匹配文件。同一文件既有已暂存又有未暂存修改时，会同时出现在两组中。
4. 使用上下箭头跳转差异，两箭头之间显示当前差异位置和总数（如 `1/4`），跳转到的变更行会高亮 1 秒后自动恢复。第一处的向上按钮、最后一处的向下按钮会置灰，不循环跳转。打开文件时定位第一处差异，仍可滚动查看完整文件；折行箭头用于切换自动换行，悬停显示「自动换行」。
5. 每 5 秒自动刷新可见窗口，重新聚焦时也会刷新。可按 `⌘R` 立即更新。最近打开的工作区会保存在本机，下次启动自动恢复。
6. 点击窗口右上角的「提交」，在展开的面板中填写说明，再点击「提交 N 个已暂存文件」。提交只使用暂存区内容，不会自动暂存其他修改；失败时保留提交说明，支持 Git 自身的提交钩子和签名设置。
7. 窗口右上角可选择远程仓库并执行拉取、推送。拉取采用 `--ff-only`，分支分叉时报告错误；推送明确指定当前分支，有上游时沿用上游分支，首次推送会设置上游。不会强制推送，也不会自动 stash。
8. 远程认证沿用本机 Git 的 SSH agent 或凭据助手。没有远程仓库、游离 HEAD、无提交、认证失败或远程拒绝等情况会禁用相应按钮或显示 Git 错误，不会代为修改全局 Git 配置。
9. 远程选择框后提供分支切换。选择本地分支会直接切换；选择当前远程下尚无本地同名分支的远程跟踪分支，会创建本地分支并设置上游。列表使用本机已有的分支记录，不自动联网获取。其他 worktree 正在使用的分支会置灰。切换沿用 Git 的本地修改保护，不强制覆盖、不自动 stash；冲突或可能覆盖文件时通过 toast 提示。成功后更新仓库分支、文件列表和双栏对比。
10. 顶部最右侧的「分支」打开分支管理弹窗。「新建分支」从当前提交创建，可选择是否立即切换；「删除分支」只删除本地分支，当前分支和其他 worktree 占用的分支不可删除。未合并到当前分支的分支默认拒绝删除，需要明确勾选强制删除。
11. 「合并」弹窗列出本地已有的提交，可按分支筛选、搜索提交说明、加载更早的记录。选择一个提交后，合并到弹窗打开时的当前分支，支持「即使可以快进，也创建合并提交」。合并包含所选提交及其祖先历史，使用标准 Git merge；不会自动获取远程记录或自动 stash。存在已跟踪文件的未提交修改时，需要先处理修改；未跟踪文件仍受 Git 覆盖保护。
12. 合并冲突会更新到文件列表，并通过 toast 提示。可在外部编辑器解决冲突、回到 GitNest 暂存并填写说明提交；也可点击顶部「合并中 → 中止合并」。分支切换和新建在合并未完成时暂停，避免打断当前合并。

## 对比规则

- 未提交文件数包含已暂存、未暂存和未跟踪文件，同一文件只计一次；不包含 Git 忽略的文件。
- 对比左侧固定为 HEAD 的完整文件。选择「未暂存」文件时，右侧是磁盘上的完整文件，包含已暂存后继续修改的最新内容；选择「已暂存」文件时，右侧是暂存区中的完整文件，即本次提交将包含的版本。两侧都可滚动查看完整上下文。
- 新增文件或尚无提交的仓库左侧为空；已删除文件右侧为空；已暂存的重命名会使用原路径读取提交内容。
- 如果磁盘内容已经恢复成 HEAD，工作区对比两栏可能相同，但暂存区仍可能存在变化；选择「已暂存」组可查看实际将提交的内容。
- 合并冲突文件左侧显示 HEAD，右侧保留磁盘上的冲突标记。
- 二进制文件、非 UTF-8 文本、超过 5 MB 的文件、Git 子模块目录会显示说明，不进行文本对比。
- 默认只扫描当前目录及一级子文件夹，不递归发现更深层的仓库，不跟随目录符号链接。

差异编辑器保持只读。Git 写操作只在用户点击相应操作时执行；暂存和取消暂存不会回退磁盘文件。尚未提供撤销文件修改、强制推送及冲突编辑功能。

## 验证

```bash
npm test
npm run build
```

Git 集成测试使用独立临时仓库及本地 bare 远程仓库，覆盖扫描和完整文件读取、暂存与未暂存并存、取消暂存、只提交暂存区、重命名/删除/首次提交、提交钩子失败、首次推送设置上游、只推送当前分支、快进拉取、拒绝分叉和非快进推送等行为。测试不会操作现有项目的文件或远程仓库。

## 源码结构

- `electron/git.mjs`：Git 扫描、状态解析、完整版本读取及受限 Git 操作。
- `electron/main.mjs`：桌面窗口、原生文件夹选择、工作区持久化和受限 IPC。
- `electron/preload.cjs`：隔离的桌面 API 桥接。
- `src/App.tsx`：工作区、仓库和变更文件界面。
- `src/components/DiffView.tsx`：本地打包的 Monaco 双栏差异编辑器。
- `src/components/ChangesPanel.tsx`：未暂存/已暂存文件及批量操作。
- `src/components/RepositoryActions.tsx`：右上角的拉取、推送及提交面板。
- `src/components/BranchActions.tsx`：顶部的分支管理、提交选择和合并操作。

界面、编辑器及 worker 均在应用内打包，运行时不依赖 CDN。
